# Custom Email Headers

Use `headers` for application-specific metadata, tracking IDs, campaign tags,
or any custom `X-…` header.

## Root vs Per-Personalization

- **Root `headers`**: applied to every personalization.
- **Per-personalization `headers`**: applied only to that personalization.
- **If the same header is in both places, the personalization value wins.**

```python
import mailchannels

mailchannels.Emails.queue(
    mailchannels.EmailParams(
        from_=mailchannels.EmailAddress(email="sender@example.com"),
        subject="Hello",
        content=[mailchannels.Content(type="text/plain", value="Hello")],
        headers={
            "X-Campaign-ID": "newsletter-2026-05",
            "X-Project": "growth",
        },
        personalizations=[
            mailchannels.Personalization(
                to=[mailchannels.EmailAddress(email="alice@example.net")],
                headers={"X-Tier": "pro"},
            ),
            mailchannels.Personalization(
                to=[mailchannels.EmailAddress(email="bob@example.net")],
                headers={"X-Tier": "free", "X-Campaign-ID": "growth-override"},
            ),
        ],
    )
)
```

## Reserved Headers — Never Set These

MailChannels controls a fixed set of message headers. The SDK pre-validates
and raises `InvalidRequestError` client-side before any request that tries
to set one of them. Header names are checked case-insensitively, so `From`,
`from`, and `FROM` are all rejected.

These headers are either generated by the API itself (`DKIM-Signature`,
`Message-ID`, `Authentication-Results`, `Received`, `Content-Type`,
`Content-Transfer-Encoding`) or derived from structured payload fields:

| Reserved header | Set via payload field |
| --- | --- |
| `From` | `from` |
| `To` | `personalizations[].to` |
| `CC` | `personalizations[].cc` |
| `BCC` | `personalizations[].bcc` |
| `Subject` | `subject` (root) or `personalizations[].subject` |
| `Reply-To` | `reply_to` (root) or `personalizations[].reply_to` |
| `DKIM-Signature` | `dkim_domain` / `dkim_selector` / `dkim_private_key` |
| `Content-Type`, `Content-Transfer-Encoding` | `content[].type` and the encoding the API chooses |
| `Message-ID` | Returned in the send response's `results[].message_id` |
| `Authentication-Results`, `Received` | Generated by the API; not user-settable |

This list mirrors the SDK's `RESERVED_EMAIL_HEADERS` constant — keep them
in sync if MailChannels changes the list upstream.

## Case Sensitivity

Header names are treated case-insensitively by MailChannels. If two keys
differ only by case, only one is used and the choice is unspecified. Pick one
canonical casing per header.

## Values

Both keys and values must be strings. Numbers, booleans, or `None` raise a
validation error before the request leaves the client.
